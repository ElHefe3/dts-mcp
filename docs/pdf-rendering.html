Adapter at a glance

The server validates and renders its own document and template to HTML. A PDF renderer interface isolates conversion; the wkhtmltopdf adapter implements the document templating system's converter settings. The server validates the returned bytes and publishes the PDF.

flowchart LR Client["MCP or HTTP client"] --> Store["Document store"] Store --> HTML["Rendered HTML"] Store --> Port["PDF renderer interface"] Port --> Adapter["wkhtmltopdf adapter"] HTML --> Adapter Adapter --> Converter["wkhtmltopdf"] Converter --> PDF["Validated PDF"] PDF --> Store Store --> Client

Text alternative: client → document store → rendered HTML and PDF renderer interface → wkhtmltopdf adapter → converter → validated PDF → client.

The adapter passes the same flags as the source system: local file access, print media, internal and external links, 300 DPI, 1.2 zoom, and outlines. Actual layout and supported features depend on the wkhtmltopdf build and installed fonts; distribution builds without patched Qt may ignore some flags.

Rendering flow

sequenceDiagram participant C as Client participant S as MCP server participant A as PDF adapter participant W as wkhtmltopdf C->>S: render_pdf(document id) S->>S: Validate document and render HTML S->>A: Convert HTML path A->>W: Run with absolute paths and PDF flags W-->>A: Temporary PDF and diagnostics A->>A: Validate PDF signature A-->>S: PDF bytes S->>S: Save validated PDF S-->>C: Metadata and PDF attachment

Text alternative: the server renders HTML, asks the adapter to convert it, validates the temporary output, saves the PDF, and returns the attachment. A failed conversion leaves the previous PDF in place.

Relative HTML assets resolve from the rendered HTML directory. Local file access is enabled to match the source system, so only use trusted templates and assets.

Setup and renderer selection

  1. Set DOCUMENT_MCP_WKHTMLTOPDF to an executable path or command name to select it explicitly.
  2. Otherwise, the server checks project-local candidates under its startup working directory.
  3. If no project-local binary exists, it uses wkhtmltopdf on PATH.
PlatformProject-local candidates, in order
Windowstools/wkhtmltox/bin/wkhtmltopdf.exe
tools/wkhtmltox/windows-x64/bin/wkhtmltopdf.exe
Linuxtools/wkhtmltox/linux-x64/bin/wkhtmltopdf
tools/wkhtmltox/bin/wkhtmltopdf
Othertools/wkhtmltox/bin/wkhtmltopdf

Relative override paths are resolved from the startup working directory. A bare executable name is searched on PATH. The supplied container installs wkhtmltopdf and Liberation fonts, maps generic font families to the corresponding Liberation faces, and sets the explicit override to /usr/bin/wkhtmltopdf. The browser uses its own fonts and screen layout; print CSS, page width, and converter versions can still change the result.

Render and retrieve

Call the MCP tool with the saved document ID:

{"id":"acme-application"}

render_pdf returns metadata and an embedded application/pdf resource. Read it again through document://renders/acme-application.pdf, or use the authenticated browser route /renders/acme-application.pdf. The SSH bridge can save the attachment locally.

Troubleshooting

SymptomCheck
Renderer cannot startCheck the override path, executable permissions and PATH. A configured override takes precedence even if it is invalid.
Conversion failsReview the error's renderer, working directory, input, output, exit status, stdout and stderr. Confirm referenced files and fonts are available to the server.
Layout or links differCompare wkhtmltopdf versions, patched Qt support, fonts, and print CSS. Test using the same converter build as the source system.
No PDF or invalid PDFCheck the converter output and available disk space. Only output beginning with the PDF signature is published; this is a basic signature check, not full PDF validation.

Diagnostics can include paths and converter output. Treat them as operational information when sharing logs.
